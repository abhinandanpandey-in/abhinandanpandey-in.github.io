CASE FILE / 001Architecture prototype

Agent-Isolate-X

Separating agent intent from execution authority

Threat. Untrusted content can attempt to redirect an LLM agent toward unintended actions or misuse of connected tools.

Approach. A zero-trust separation model between a privileged controller and a quarantined executor. The design goal is to make capabilities and permissions explicit rather than relying on the model to reject every malicious instruction.

Evaluation questions. Can the executor reach privileged tools? Are requests constrained to an allowlist? Can the system log and reject unauthorized actions? These need reproducible tests against the implementation.

CASE FILE / 002RAG pipeline

Threat-Intel-RAG

Query public vulnerability intelligence locally

Stack. CISA Known Exploited Vulnerabilities data, LangChain, Chroma, and a Qwen2.5 LoRA workflow.

Next tests. Retrieval recall, source traceability, dataset freshness, and answer faithfulness against a labelled query set.

CASE FILE / 00348-hour prototype

Local Healthcare RAG

Local inference with a deterministic safety layer

Problem. Explore a local question-answering flow where privacy, retrieval quality, and unsafe responses matter alongside fluency.

Stack. Phi-3, Ollama, FAISS, and a deterministic safety layer. The prototype was built in 48 hours.

Limit. A safety layer does not imply clinical validation. It needs explicit tests for unsafe, ambiguous, and out-of-scope questions.

02 / Research agenda

Find the failure mode. Bound the impact.

My research interests focus on the security properties around LLM applications: how untrusted input changes behavior, how tools expose authority, and how architecture can reduce the consequences of model failure.

research_mode = "adversarial"
default_trust = "none"

R/01

Indirect prompt injection & tool hijacking

Trace how malicious instructions in retrieved content, documents, or tool outputs can influence action selection and control flow.

R/02

Agentic system boundaries

Study permission separation, constrained execution, tool allowlists, audit trails, and ways to contain compromised agent behavior.

R/03

RAG faithfulness & evidence tracking

Test whether generated answers stay within retrieved evidence, preserve source traceability, and expose missing or stale context.

R/04

Adversarial evaluation

Build repeatable test suites with explicit threat assumptions, labelled cases, observed outcomes, and documented limitations.

R/05

Local-first AI security

Investigate privacy and operational tradeoffs in local model serving, retrieval pipelines, and restricted tool execution.
